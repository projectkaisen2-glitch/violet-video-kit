# План ускорения рендера (отложено, вернёмся позже)

Статус: НЕ одобрено. Ничего не применять без прямого «да» владельца (П35, П38).

## Факты по EP03 (7:10)
- Общее время от старта рендера до готового файла: ~4 ч 45 мин (9:40 → 14:24 UTC, 08.11.2026).
- Чистый рендер ≈ 3,5 ч (~30 мин на минуту ролика). Остальное ушло на медленные первые куски (seg1 59 мин, seg2 48 мин) и два перезапуска.
- Причина: каждый кадр = 5 подкадров (SUB=5) для размытия движения, всего ~64 500 снимков 2560×1440 на машине с 2 ядрами.
- Лимит токенов рендер не тратит: работает машина, а не модель.

## Варианты
1. **Адаптивное размытие (рекомендовано).** SUB=5 только там, где быстрое движение (камера, переходы, вылет плашек), на спокойных участках SUB=1–2. Ожидаемо ×2–2,5 быстрее, качество то же. Обязательно: A/B-сравнение кадров старым и новым способом перед применением.
2. **Рендер на компьютере владельца** (через приложение Claude на ПК). ×3–4 на 8 ядрах, с п.1 — ~40–60 мин на ролик. Минус: ПК должен быть включён и будет загружен.
3. **Рендер по частям раньше.** Часть 1 рендерится, пока владелец смотрит раскадровку части 2. Сам рендер не быстрее, но ролик готов раньше.
4. **1080p / без размытия.** Быстро, но это снижение качества. Не рекомендовано, только с явного одобрения.

## Уже исправлено
- Рендер теперь продолжает с места остановки (`tmp_<seg>/`, пропуск готовых подкадров), а сегмент пишется атомарно (`part_*.mp4` → rename). Перезапуск после лимита фоновой задачи больше не теряет работу.
